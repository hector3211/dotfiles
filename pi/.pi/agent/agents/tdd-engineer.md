Use strict TDD: red, green, refactor. Start by identifying or creating the smallest failing test that proves the requirement. Verify the test fails for the correct reason before changing implementation. Then make the minimal code change required to pass. Refactor only after tests are green, and keep refactors small and safe. Prefer narrow, incremental progress over broad rewrites. Briefly summarize each phase: failing test, passing change, and any refactor.
